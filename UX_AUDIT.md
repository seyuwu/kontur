# Проверка UX/UI — 16 октября 2026

Проверена реализованная версия «Контура»: вход, регистрация, подключение, кабинеты врача и пациента. Это проверка интерфейса и технических сценариев на синтетических данных. Она не доказывает удобство в реальной практике и не оценивает ещё не реализованные клинические функции.

## Результат

- Обе строки «Между контактами» целиком являются кнопками. Свободное поле, текст, иконка и стрелка выполняют одно действие. Есть hover, видимый фокус и управление Enter/Space.
- Строка пациента в таблице открывается по всей площади. Для клавиатуры оставлена одна кнопка имени вместо двух одинаковых остановок. Контакты в расписании также открываются целой строкой.
- Пять сквозных тестов прошли; итоговая production-сборка прошла и запущена.
- В 25 проверенных сочетаниях экрана и размера окна после точечного подтверждения нет обнаруженных axe нарушений, горизонтальных переполнений и активных целей меньше 44 × 44 CSS px. Для checkbox измеряется вся кликабельная подпись.
- Ошибок JavaScript в проверенных состояниях нет. Manrope загружен локально. Подписи оси графика на 320 px отрисовываются размером 12 px.

Автоматический axe оставляет отдельные проверки контраста со статусом incomplete: SVG, нативные поля и слои требуют ручной проверки. Нулевое число обнаруженных нарушений не является сертификатом соответствия WCAG.

## Найденные и исправленные проблемы

| Приоритет | Проблема и её влияние | Изменение |
|---|---|---|
| P1 | Часть аватаров и нейтральных статусов не достигала контраста 4.5:1 | Затемнены соответствующие оттенки; повторная проверка не обнаружила прежних нарушений |
| P2 | В действиях пациента нажималась только маленькая стрелка | Одна нативная кнопка занимает всю строку, без вложенной кнопки |
| P2 | Таблица и расписание требовали попадания в отдельные элементы | Целые строки выполняют одно действие, без дублирующей остановки клавиатуры |
| P2 | Фильтр сообщений исчезал на телефоне вместе с sidebar | Добавлен в общий набор из четырёх фильтров; на телефоне сетка 2 × 2 |
| P2 | У ряда кнопок, ссылок и полей была малая область нажатия | Основные активные цели увеличены до 44 px; фокус и наведение сохранены |
| P2 | Разделы пациента не отражались в URL и истории браузера | URL раздела, Back, сохранение раздела после перезагрузки, фокус заголовка и начало нового раздела сверху |
| P2 | Сетевой сбой мог показывать технический текст на английском | Общие русские сообщения об ошибке и восстановлении; ввод остаётся в форме |
| P2 | Редактирование во время отправки могло потеряться после ответа | Поля блокируются на время отправки; после ошибки снова доступны. Изменённый запрос получает новый ключ |
| P2 | Escape мог нативно закрыть панель во время сохранения, оставив её состояние открытым | Согласованы cancel и controlled state; закрытие блокируется на время отправки |
| P2 | Чат мог прокручивать всю страницу и отнимать позицию чтения | Прокручивается только контейнер сообщений; новые сообщения следуют вниз, если пользователь уже находится у конца |
| P2 | На узком экране график уменьшал подписи вместе со всем SVG | ViewBox подстраивается под фактическую ширину; высота и подписи остаются читаемыми |
| P2 | После уточнения статуса он не помещался в приветствии на 320 px | На телефоне приветствие и статус располагаются последовательно |
| P2 | Фоновые события самоотчёта дублировали сам самоотчёт в истории врача | Для checkin используется одна запись с переходом к источнику |
| P2 | Мобильное уведомление могло перекрывать нижнюю навигацию | Уведомление расположено над ней, учтён safe area |
| P2 | Врач видел в своём чате подпись «С ведущим врачом»; «На связи» могло означать присутствие онлайн | Подпись зависит от собеседника; у пациента статус «Врач подключён» |

## Оценка по направлениям

| Направление | Подтверждено | Практический предел проверки |
|---|---|---|
| Доступность | Семантические кнопки, фокус, клавиатура, подписи и состояния, axe, увеличенные цели | Не проводился сеанс с экранным диктором; incomplete проверки не закрыты сертификатом |
| Производительность | Standalone-сборка, локальные шрифты, SVG без растровых загрузок; ошибок выполнения нет | LCP/INP, медленная сеть и нагрузка большой клиники не профилировались |
| Адаптивность | Основные размеры 320/390/768/1440; устранены найденные переполнения | Эмуляция не заменяет физическую клавиатуру телефона, Safari и Android |
| Визуальная система | Сохранены палитра, Manrope, общий язык состояний; обновлены изменённые компоненты DESIGN.md | В CSS остаются отдельные буквальные значения и неполная машиночитаемая шкала |
| Целостность сценариев | Сквозные тесты реального подключения и обмена данными; сохранение контекста; обработка ошибок | Функциональность клинического приёма ещё не реализована целиком |

Статический Impeccable detector выдал 177 advisory замечаний: 39 по цветам, 130 по размерам шрифта, 8 по скруглениям. Все относятся к неполному описанию значений CSS в машинном слое DESIGN.md; не-advisory замечаний не было. Это не 177 пользовательских ошибок. После сканирования точечно обновлена документация изменённых компонентов; повторный detector ради снижения счётчика не запускался. Повтор исходной команды был нужен один раз, поскольку первый вывод был обрезан.

## Что ещё проверить с людьми

1. Врач самостоятельно находит пациента, открывает изменение и его источник, пишет ответ и сохраняет заметку с датой. Наблюдать, где он ищет действия и что принимает за подтверждённый факт.
2. Пациент без подсказок подключается по коду, делает отметку, просит о контакте, пишет сообщение и находит предыдущую запись. Проверить понимание статусов «сохранено», «прочитано» и ожидания ответа.
3. Пройти те же задачи на физическом телефоне с открытой клавиатурой и на увеличенном масштабе; проверить экранным диктором. QR с другого устройства требует доступного адреса сервера.

Оставшиеся ограничения текущего пакета: черновики живут в памяти вкладки и не восстанавливаются после перезагрузки или завершения сессии; показаны последние 30 отметок и 50 сообщений без загрузки более ранней истории; нет самостоятельного восстановления пароля. Перед полноценным использованием эти сценарии требуют отдельной реализации. Планы, клинические шкалы, критическая доставка и AI-импорт остаются в DEVELOPMENT_PLAN.md.

## Как повторить

При запущенных приложении, PostgreSQL и подготовленной очереди:

```powershell
npm run build
npm run start
# В отдельном терминале:
npm run test:e2e
node scripts/ux-audit.mjs after
```

`node scripts/ux-audit.mjs confirm` проверяет исправленные узкие места. Изображения и исходные JSON сохраняются в игнорируемой папке `.impeccable/review/ux-*`. Не запускайте браузерные наборы одновременно: они соблюдают настоящий серверный лимит входов.


## Карточка пациента: приоритет сведений, 21 октября 2026

По замечанию пользователя обзор перестроен: состояния и ограничения, аллергии и препараты со статусами приёма видны без открытия панели. На широком экране рядом находятся ближайший контакт, последний самоотчёт, ведущий врач и подключение; ниже — компактный текущий план. Основная колонка продолжает сведения заметкой, событиями, изменениями и динамикой. На телефоне сохраняется одна колонка.

Назначение и история анкет вынесены в локальную вкладку «Анкеты» с сохранением пациента в URL. Пустое направление свёрнуто до заголовка и действия; ошибки и существующие направления не скрываются. Неизвестность не обозначается как отсутствие; у прекращённых препаратов остаётся явный статус. Сводка показывает до трёх записей категории и явный переход к остальным.

Автоматическая проверка охватывает пустую и заполненную карточку, ширины 1609/1440/390/320, отсутствие горизонтального переполнения, переходы/перезагрузку вкладки и serious/critical axe-проверки. Это техническая проверка, а не исследование удобства с врачами.


Каталог: при переключении «Внимание» события появляются под постоянной панелью фильтров и поиска внутри общего списка. Панель и ближайшие контакты сохраняют положение. Секция событий сохраняет переключение активных/разобранных, обновление и открытие разбора. Координаты панели проверены на 1575/390/320px.
