## Зафиксированное решение: полезные алерты и роль LLM

Пользователь подтвердил 17 октября: главный результат — полезное уведомление с предложенными действиями, после которого врач оценивает ситуацию, принимает решение и фиксирует результат.

1. Анкета → проверка полноты → расчёт по определению инструмента → проверенные правила → алерт и подходящие действия из каталога → решение врача → последующее наблюдение.
2. Формулы, срочность, поддерживаемые признаки критического события и допустимость системных предложений не поручаются LLM. Неполнота или неизвестность не превращаются в благополучный результат.
3. На первом проходе объяснения и предложения формируются шаблонами с реальными источниками. Редактор правил, свободный медицинский чат, собственная модель и дообучение не нужны для первой версии.
4. Готовая LLM добавляется для разбора неструктурированных историй с исходными фрагментами и проверкой врача. Дополнительные резюме допустимы только с опорой на проверенные факты; модель не добавляет свободные назначения.
5. Критический путь продолжает работать при отключённой модели. Создание задачи, отправка, подтверждённая доставка, просмотр, принятие в работу и завершённое действие измеряются раздельно.
6. Защита должна показывать все восемь задач кейса, включая терапию, переносимость, приверженность и маршрутизацию. Один алертинг не закрывает полный кейс.

## Общие правила

- Завершать сквозные пользовательские сценарии: интерфейс, проверка доступа, модуль, база, достоверный статус, проверка результата.
- Брать сначала один клинически проверенный пример, затем расширять покрытие. Синтетический непроверенный пример обозначать как таковой.
- Роли, версии, происхождение данных и журналирование закладывать с первой применимой операции.
- Критические проверки выполнять на этапе появления функции; последний этап не заменяет их.
- Применять реальные данные только в отдельно подготовленном и проверенном контуре. Разработка и демонстрация по умолчанию на синтетических пациентах.
- Ошибку, отсутствие данных и незавершённую операцию не отображать как успех.
- AI-результат не подтверждает план и не заменяет проверенные детерминированные правила.
- Сохранять работающий сценарий предыдущего этапа; показывать результат в браузере после каждого этапа.
