# Самоотчёты, обобщения и методики F40

Оценка самочувствия 1–5 убрана из формы, карточки врача, истории и контекста разбора. Пациент может отправить текст или только просьбу связаться. Старые баллы остаются в базе для сохранности истории; новые записи сохраняются с `score = null`. Миграция `20261023000000_text_checkin` делает колонку необязательной.

## Groq: обобщения для врача

Обобщение доступно в обзоре карточки, отправленной анкете и разборе события. В контекст входят до пяти последних самоотчётов, анкет и сообщений пациента, текущие подтверждённые клинические сведения, план, заметка врача и выбранное событие. ФИО и контакты не добавляются отдельными полями; свободный текст может их содержать. Этот контур предназначен только для вымышленных данных.

Баллы пересчитываются программным модулем по закреплённой версии определения. LLM получает готовые результаты и текст ответов. Она возвращает факты с цитатами и, для события, идентификаторы предложенных действий из его закрытого списка. Новые назначения и действия модель не создаёт. Сервер проверяет формат, наличие цитат в соответствующем источнике и принадлежность действий списку. Эти проверки не доказывают смысловую точность: сводку проверяет врач. Если данные или событие изменились во время запроса, результат отклоняется. Сводки не сохраняются автоматически в клинические сведения, не отправляются пациенту и не меняют статус события.

Подключение:

1. Добавить `GROQ_API_KEY` в локальный `.env`.
2. Выполнить `npm run llm:configure`. Команда включает извлечение документов и обобщения, только если ключ задан.
3. Перезапустить web и worker.
4. Выполнить `npm run llm:check-summary` для живой проверки на вымышленном примере; `npm run llm:check` проверяет отдельный сценарий извлечения документов.

Используются `LLM_SUMMARY_ENABLED=true`, `GROQ_SUMMARY_MODEL=openai/gpt-oss-20b` и `DEMO_MODE=true`. Модель также может быть `openai/gpt-oss-120b`. Ключ остаётся на сервере. Без ключа кнопка объясняет настройку; подставной сводки нет. В этой сессии ключ отсутствовал, поэтому реальная точность и доступность Groq не проверены.

## Все 19 методик в каталоге

Карточка врача → «Анкеты» → «Все методики из рекомендаций». Каталог содержит описание, текст источника, страницы и статус для каждого приложения Г1–Г19. Исходный PDF доступен авторизованным пользователям по ссылке из методики, с проверкой SHA-256.

| Приложение | Реализовано |
| --- | --- |
| Г1 HAM-A | Заполняет врач; сумма и психическая/соматическая составляющие |
| Г2 SCL-90-R | 90 ответов, GSI, 9 подшкал, дополнительные пункты, PSI, PDSI. При PSI=0 PDSI не определён. Пункт 56 в DEP перенесён буквально по PDF и отмечен для сверки |
| Г3 ИТТ | Два отдельных бланка: СТ-С и СТ-Л, сырые суммы 0–45. Взвешенные подшкалы и станайны пока не реализованы |
| Г5 BAI | Существующий перенос, 21 пункт и диапазоны PDF |
| Г6 SPRAS | 35 ответов, сумма 0–140 |
| Г17 BFNE | 12 ответов, сумма 12–60 |
| Г18 GELOPH-15 | 15 ответов, общее среднее, общая сумма и средние двух подшкал; категория автоматически не присваивается из-за промежутков в порогах PDF |
| Г4 STAI | Текст доступен; расчёт заблокирован: прямые/обратные пункты расходятся с формулировками |
| Г16 LSAS | Текст доступен; в описании ответы 0–3, в бланке 1–4; пороги пересекаются |
| Г19 CGI | Текст доступен; врачебная шкала, в бланке пропущен вариант и расходится ключ индекса эффективности; суммарный балл не рассчитывается |
| Г7–Г15 | Справочные карточки: в PDF нет полного бланка и/или ключа/нормативов; для цифрового расчёта нужны руководства |

Итого: 19 карточек методик, 8 цифровых бланков для 7 методик. Импорт не присваивает клинического одобрения. HAM-A не может заполнять пациент; черновик врача не раскрывается пациенту. Черновики самоопросников по-прежнему не раскрываются врачу до отправки. Сигналы высокого показателя и предлагаемые действия — учебный рабочий процесс, без автоматического определения срочности.

Повторяемый импорт текста: `scripts/import-f40.py`, Python с `pypdf`. Публикация определений: `npm run db:seed-assessments`.

## Проверка уведомлений на ПК

1. Запустить `npm run dev:local` и открыть **http://localhost:3000** в обычном окне Chrome/Edge/Firefox. Встроенный просмотр приложения может не предоставлять необходимые API. HTTP по IP другого компьютера не подходит: нужен HTTPS с доверенным сертификатом.
2. В кабинете врача нажать значок телефона в верхней панели. Диагностика отдельно объясняет небезопасный адрес, отсутствие API, установку на iOS и блокировку разрешения.
3. Нажать «Проверить показ на ПК». Это локальный `ServiceWorkerRegistration.showNotification`: он проверяет разрешение и системный показ, без сервера доставки. Если команда выполнена, но уведомление не видно, проверить центр уведомлений Windows, разрешения для браузера и режим «Не беспокоить».
4. Для настоящей доставки выполнить `npm run push:configure-local`, перезапустить сайт, отдельно запустить `npm run worker`. Подключить уведомления и нажать «Отправить проверку». VAPID-ключи сохраняются в `.env`, существующая пара не заменяется.
5. Смотреть статусы отправки в панели. «Принял push-сервис» не равно показу, а показ не подтверждает прочтение. Панель показывает, если worker не отвечает.

Медицинские данные и рекомендации не выводятся на экран блокировки. Сводка и предложения доступны врачу внутри события. Реальный показ уведомления операционной системой и доставка через внешний push-сервис требуют проверки на устройстве; автоматические тесты используют подменённый транспорт.

API Groq реализован по [документации структурированных ответов](https://console.groq.com/docs/structured-outputs). Условия браузерной доступности: [MDN: secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts).
