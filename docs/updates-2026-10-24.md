# Приём, срок связи и Mistral

## Дата следующего приёма

По уточнению пользователя оставлено одно поле — «Дата следующего приёма», только календарная дата. Поля «Связаться до», времени, формата и места встречи убраны из рабочих форм. Дату можно указать в заметке врача до появления подтверждённого плана, затем менять через новую версию плана. Одно значение показано в карточках врача и пациента и в памятке.

Версии старых планов не переписываются. Если в старом плане был отдельный согласованный приём, для единой даты используется день этого приёма. Просьба пациента связаться не создаёт дату приёма.

## Уведомления

Внешний push создаётся **только при сохранении пациентом просьбы «Хочу, чтобы врач связался со мной»**. Текст без просьбы, результаты анкет, изменения плана и сообщения не создают автоматический push. Результаты анкет, их рекомендации и ссылки на источники остаются в кабинете врача. Тестовая отправка из настроек устройства доступна отдельно.

Push содержит фиксированный текст просьбы, без имени и медицинских данных, и открывает карточку пациента. Повтор отправки того же самоотчёта не создаёт дубль. Подтверждённая врачом просьба не отправляется из оставшейся очереди. Перед отправкой проверяются действующая сессия, устройство и ведущий врач. Старые ожидающие push/email по анкетам отменяются; успешная история доставок сохраняется.

## Mistral

На 24 октября 2026 в локальном `.env` выбраны `LLM_SUMMARY_PROVIDER=mistral`, `DOCUMENT_EXTRACTION_PROVIDER=mistral`, обе модели — `ministral-14b-latest`. Ключ хранится только локально. `mistral-small-latest` возвращала 429; Ministral 3B, 8B и 14B ответили успешно. Автоматического перехода между моделями или провайдерами нет.

Реальный запрос обобщения анкеты прошёл проверку структуры, цитат и разрешённых действий. Извлечение прошло 6/6 коротких учебных примеров: аллергия, текущий и прекращённый приём, отрицание, неопределённость и посторонняя команда. Это технический набор, не клиническая валидация. В облако разрешены только вымышленные учебные данные. Извлечение ограничено 8 000 символами; результат сверяет врач.

Проверить повторно:

```powershell
npm run llm:check-summary
npm run llm:check
npm run llm:evaluate
```

В интерфейсе: карточка → «Обобщить с LLM»; отправленная анкета → обобщение; клинические сведения → документ → согласие на передачу → «Извлечь кандидаты фактов». Сводка не меняет баллы, назначения или решения врача.

Для проверки push: подключить устройство в кабинете врача; в отдельном профиле браузера войти пациентом и сохранить просьбу связаться. Обычный текст или отправка анкеты должны оставить результаты в кабинете без системного уведомления. Автотесты используют имитацию транспорта; настоящий показ проверяется на устройстве.

## Исправление обобщений

Кнопка называется «Обобщить» до и после результата. Источники передаются читаемым текстом без вложенного JSON-экранирования; цитаты по-прежнему проверяются дословно. На синтетическом примере прежний формат дал 3/3 INVALID_EVIDENCE, исправленный — 3/3 успешных ответов примерно за 4–5 секунд. Это технический пример, не гарантия точности на всех данных.

Минутная блокировка убрана: блокируются только одновременно выполняемые запросы одного врача. После любого завершения, включая ошибку, блокировка снимается. Запрос к модели ограничен 15 секундами; можно сразу повторить. Ошибки квоты, сети, таймаута и неподтверждённых цитат показываются отдельно. Коды сбоев журналируются без текста пациента и ключей.
