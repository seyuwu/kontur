# Обмен данными версии 1

Контракт `1.0` отделён от модели Prisma и от экранов приложения. Подготовка снимка находится в `src/modules/integrations/index.ts`, схема в `contract.ts`, форматы JSON и CSV в `serialize.ts`. Смена внешнего формата не требует изменения расчёта шкал, расписания или интерфейса пациента.

## Доступ

`GET /api/integrations/v1/export?patientId=ID&format=json` или `format=csv`. Используется существующая сессия врача; выгружается только его пациент. Пациент, чужой врач и анонимный запрос доступа не получают. Чтение регистрируется в аудите; ответ запрещено кешировать. Внешние произвольные адреса не принимаются, автоматической пересылки третьей стороне нет.

`GET /api/integrations/v1/schema` возвращает JSON Schema для врача. В карточке пациента во вкладке «Данные» доступны обе выгрузки.

## Состав

Идентификаторы карточки и внешний reference, текущая версия клинических сведений, подтверждённый план с лекарствами и расписанием, страница из не более 20 назначений анкет и их отправленные результаты. Есть код и версия методики, исходные идентификаторы ответов, дата снимка и область выгрузки. Черновики ответов, переписка, сессии, пароли, API-ключи и полный журнал событий не экспортируются. JSON Schema — источник типов внешнего контракта.

Для следующих назначений передайте `cursor` из `assessments.nextCursor`. Это постраничные снимки, а не одна транзакционная полная выгрузка всей истории. При изменении пациента во время чтения сервер возвращает 409, выгрузку нужно повторить. CSV содержит строки разных типов с фиксированными столбцами; формулы Excel и кавычки экранируются.

## Подключение внешней системы

Потребитель читает JSON, проверяет `contractVersion` и сопоставляет собственные идентификаторы с `patient.externalReference`. Изменение схемы с нарушением совместимости требует нового номера и отдельного маршрута, старый контракт сохраняется. CSV пригоден для импорта в аналитические инструменты. Этот формат не является HL7 FHIR и не подтверждает совместимость с конкретной МИС. Для продуктивного машинного обмена нужны согласованные авторизация сервисов, сопоставление полей, права и обработка персональных данных. Внешняя запись клинических назначений сейчас не открыта.

Проверки: `tests/unit/integrations.test.ts`, `tests/e2e/integrations.spec.ts`. Расширение анкет проверяется командой `npx tsx scripts/check-extensibility.ts`; локальная публикация учебного JSON — `npm run assessment:publish -- definition.json`. Клиническое одобрение эта команда не присваивает.
