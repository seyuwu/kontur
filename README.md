# Контур

Рабочая основа цифрового ассистента врача: Next.js / React / TypeScript, PostgreSQL, Prisma, Better Auth и Graphile Worker.

Актуальный сценарий: [Назначения врача и главная пациента](docs/patient-assignments.md).

## Что уже реализовано

- Серверный вход, отдельные роли, кабинеты терапевта / психиатра / пациента и проверка доступа к своим карточкам.
- Создание карточки, одноразовые QR / коды, запрос связи и подтверждение врачом.
- Серверный поиск и фильтры по всем своим пациентам, список по 20 кратких строк, отдельная карточка и раскрытие исходного самоотчёта.
- Главная пациента: актуальные анкеты, лекарства и задачи по датам. Один вход в чат; просьба связаться отправляется вместе с сообщением.
- Заметка врача и дата следующего приёма, черновики при переключении разделов.
- PostgreSQL-миграции, синтетический seed, транзакционная запись самоотчёта и технического фонового задания.
- Версионные определения анкет, назначение, приватный серверный черновик, проверка полноты и отправка с защитой от повторов и конфликтов вкладок.
- Учебные события по ответам: исходные данные, объяснение, предложения действий, принятие в работу и зафиксированный результат врача.
- Страницы новых анкет и событий по 20 записей; подробности события загружаются при открытии. Неизменившийся `/api/workspace` отвечает 304 после проверки сессии и лёгкой проверки версии данных.
- Счётчики по всей истории, включая старые просьбы и сообщения; догрузка переписки по 50 без ложного прочтения невидимой истории. Поиск, фильтр и позиция списка сохраняются в адресе; черновик сообщения — в текущей вкладке при переходах.

Это учебная версия на вымышленных данных. Добавлен каталог всех 19 методик F40, 8 учебных бланков для 7 методик и сохраняемые обобщения Mistral/Groq с цитатами. Часть методик пока доступна только как описание из-за неполноты или противоречий PDF. Добавлены вводимые и подтверждаемые врачом учебные лекарственные назначения с датой, временем и напоминаниями. Клиническое одобрение и экстренная доставка не реализованы. Запрос «хочу связаться» не определяет критическое состояние.

Также доступна оригинальная учебная анкета «Связь и понятность следующих шагов»: два вопроса об организации контакта, без диагностики и медицинской срочности. Назначение: карточка врача → «Анкеты пациента» → «Назначить анкету». Заполнение: пациент → «Сегодня» → «Анкеты от врача». Разбор: врач → «События по анкетам» → исходные ответы / предложения → «Взять в работу» → действие и результат. Просмотр, открытие чата и выполненный контакт — разные действия.

## Локальный запуск

Требуется Node.js, совместимый с закреплёнными зависимостями, и PostgreSQL. На машине разработки используется Node.js 22.22.3 и отдельный PostgreSQL 18.2 на 127.0.0.1:55432.

```powershell
npm ci --legacy-peer-deps
npm run db:local
npm run db:generate
npm run db:migrate
npx tsx scripts/migrate-worker.ts
npm run db:seed
npm run dev
```

В другом терминале:

```powershell
npm run worker
```

Открыть http://localhost:3000. На странице входа есть три демонстрационных аккаунта; кнопки проходят обычную серверную аутентификацию. Для самостоятельного пациента доступна регистрация.

### PostgreSQL

`db:local` создаёт отдельный кластер в `.local/postgres`, генерирует `.env`, если его ещё нет, и слушает только loopback. Исходные существующие базы не используются. На этой машине бинарники находятся в `E:/programs/postgre/bin`; на другой машине задайте `POSTGRES_BIN` со своим каталогом бинарников или используйте Docker.

Секреты из `.env` не коммитятся и не печатаются. Для Docker заполните `.env` по примеру `.env.example`; `POSTGRES_PASSWORD` и пароль в `DATABASE_URL` должны соответствовать. Одновременно запускайте один вариант PostgreSQL на порту 55432.

Новые миграции требуют pg_trgm и поддержку ICU: они добавляют индексы и Unicode-сопоставление имени / номера карты для поиска кириллицы независимо от локали базы. На локальном PostgreSQL 18.2 применены; Docker-контур этой проверкой не испытывался. Существующие значения не удаляются.

```powershell
docker compose --env-file .env -f infra/compose.yaml up -d postgres
```

После этого выполните генерацию, миграции, подготовку очереди и seed из списка выше. Версия Prisma намеренно закреплена на стабильной 7.10.1, а не на 8.0.0 release candidate, которую реестр предлагал под latest во время установки.

### Доступ с телефона

Ссылка с `localhost` работает только на том устройстве, где запущен сервер. Для реальной проверки QR с телефона нужен доступный по сети адрес или HTTPS-контур и соответствующие `APP_ORIGIN` / `BETTER_AUTH_URL`. Изменение адреса требует перезапуска. Одноразовый QR содержит секрет во fragment, который не отправляется серверу при загрузке страницы; после чтения секрет временно хранится только в сессии этой вкладки до запроса связи. Медицинские данные до подтверждения закрыты.

## Проверка

```powershell
npm run typecheck
npm run test:unit
npm run build
npm run test:e2e
```

Для запуска собранной версии используйте `npm run start` после `npm run build`. Скрипт копирует статические ресурсы в standalone-пакет и запускает его сервер. Worker запускается отдельно.

Сквозные проверки требуют запущенные приложение, БД и подготовленную схему очереди. Они проверяют запрет чужого доступа и повышения роли, сохранение контекста / черновиков, подключение с подтверждением, самоотчёт, повтор отправки и переписку. Созданные тестами вымышленные карточки и аккаунты удаляются самими тестами.

17 октября: сборка и проверка типов успешны; 6 модульных и 19 сквозных проверок прошли. Проверки включают анкеты и разбор, 120 пациентов на шести страницах, поиск за прежним пределом 100, регистр кириллицы и буквальные % / _, счётчики старой истории, доступ / ETag, back / reload, черновик, отозванную карточку, гонку ответов и догрузку переписки. На новых диалогах и каталоге axe не обнаружил нарушений; проверены ширины 320 / 390 / 1440. Это техническая проверка, не клиническая валидация и не пользовательское исследование.

Врачебный GET `/api/workspace` заменён на `/api/patients` и `/api/patients/:id`, старый GET врачу отвечает 410. Команды POST сохранены; `read-messages` теперь требует конкретные `messageIds` (до 50), общая отметка всей истории удалена.

Обычный `db:seed` публикует учебное определение без назначения пациентам. Для уже заполненной демонстрационной базы: `npm run db:migrate`, затем `npm run db:seed-assessments`. Опубликованное определение с теми же code / version нельзя заменить другим содержимым; нужна новая версия. Нет HTTP-редактора публикации, а `DEMO_MODE=false` запрещает использование учебного определения.

Для браузерных тестов установите Chromium через `npx playwright install chromium` либо задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. На этой машине используется уже установленный Chromium. Скрипт `node scripts/inspect.mjs` сохраняет изображения основных экранов в `.impeccable/review`.

Полный проход реализованных экранов на доступность, размеры целей и адаптивность: `node scripts/ux-audit.mjs after`. Итог текущего UX/UI-аудита и его ограничения — в UX_AUDIT.md. Сквозные тесты дополнительно проверяют целые строки действий, клавиатуру, историю браузера, сохранение ввода при сбое сети и панель во время медленной отправки.

## Текущее ограничение фоновых задач

Задание `workspace_event` подтверждает работу очереди и обрабатывает только технический идентификатор события. Оно не отправляет сообщения. Отдельные задания `document_extract` и `notification_email` обслуживают импорт и техническую отправку email. Статус SMTP ACCEPTED означает только принятие письма почтовым сервером; прочтение и экстренное реагирование не подтверждаются.

Планы реализации: DEVELOPMENT_PLAN.md. Архитектура: ARCHITECTURE.md. Сценарии: UX_SCENARIOS.md.

## План наблюдения

Врач готовит план в карточке: цель, памятка пациенту, дата контакта и до восьми задач. «Сохранить и проверить» сохраняет приватный черновик; «Подтвердить и показать пациенту» выпускает версию. Между сохранением и подтверждением приложение проверяет новые данные и изменение плана. Сохранённый черновик можно продолжить после перезагрузки, несохранённый текст остаётся только в текущей вкладке.

Пациент видит действующую версию, задачи, историю и может передать вопрос по задаче прямо в переписку. Для анкеты открывается существующая панель заполнения. Старые версии сохраняются; отметки задач являются самоотчётами. Лекарственные назначения и клинические рекомендации этот модуль пока не оформляет. Миграция `20261018000000_care_plan` добавочная, повторный seed не требуется.

## Клинические сведения

В карточке врача появились сведения о состояниях / ограничениях, аллергиях / реакциях и сообщённом приёме препаратов. Каждый раздел отличает неизвестность от отрицательного ответа с источником. Записи содержат источник и известную дату, препараты — отдельный сообщённый статус приёма и режим из источника. Это не назначение и не автоматическая проверка противопоказаний.

Врач сохраняет новую версию после проверки ввода; пациент не получает приватный раздел как часть плана. Конкурирующая вкладка не перезаписывает данные, сетевой повтор не дублирует версию, история загружается отдельно. Новые сведения делают черновик плана устаревшим; из действующего или исторического плана можно открыть использованную версию. Миграция `20261018010000_clinical_profile` добавочная, повторный seed не нужен.
У планов, созданных до добавления модуля сведений, ссылки на исходную версию нет: история не достраивается задним числом.


## Действия из события

В панели события врач проверяет ответы, использованные версии сведений и плана, готовит и отправляет сообщение пациенту, затем отдельно фиксирует фактический результат. Основание сохраняется версией. При новых данных действие блокируется до явной проверки; черновик текста остаётся в текущей вкладке. Предыдущие основания доступны для чтения.

Сохранённое сообщение отличается от прочтения и состоявшегося контакта. Для другого согласованного канала результат вносит врач; система не выдаёт его за автоматически подтверждённый. Повтор команды после сетевого сбоя не создаёт дубликат. Примените добавочную миграцию `20261018020000_review_decisions` командой `npm run db:migrate`; seed повторять не нужно. Каталог пока организационный, клинические рекомендации не подключены.

Проверка продолжения 18 октября: сборка и типы успешны, 10 модульных и 35 сквозных тестов прошли. Детали сценариев и ограничения — IMPLEMENTATION_CHECKS.md.


## Сопровождение, история и документы — 18 октября

Ежедневные договорённости отмечаются отдельно за каждый день: выполнено / частично / не выполнено / не уверен. Отсутствие отчёта выделено отдельно. Исправление сохраняет предыдущую запись; вопрос врачу одновременно появляется в переписке. Это самоотчёты по рекомендациям, не лекарственные назначения и не подтверждённая приверженность терапии.

Пациент может сообщить о симптоме или возможной реакции. Запись связана с действовавшим планом; причинную связь система не устанавливает. Врач отдельно отмечает просмотр. Направление к психиатру подтверждает врач: обязательно / желательно, вручную выбранная срочность, основания и дальнейшие шаги. Организационные статусы и история доступны обоим участникам; запись в клинику не выполняется.

В «Динамике» есть полная история по 30 записей с периодом и догрузкой; разные инструменты сохраняют свои коды и версии. Из подтверждённой версии плана можно скопировать проект записи врача и открыть памятку пациента для печати через Ctrl+P. Несохранённые правки и приватные сведения в памятку не включаются. Приглашение теперь можно отозвать.

## Импорт текста и необязательная LLM

Врач → клинические сведения → источники: вставить текст (40–60000 символов), сохранить закрытый неизменяемый источник. PDF, DOCX и сканы пока не принимаются. Ручной редактор доступен при отключённом AI.

Для извлечения задайте `DOCUMENT_EXTRACTION_ENABLED=true`, `OPENAI_API_KEY`, `OPENAI_EXTRACTION_MODEL` и перезапустите web / worker. Модель выбирается настройкой, значения по умолчанию нет. Используется Responses API со строгой JSON-схемой и `store:false`; это не обещание нулевого хранения провайдером. Перед передачей текста требуется явное подтверждение врача. Работу с реальными данными здесь не проверяли.

Worker ограничивает время и повторы, сохраняет версию инструкции / модели и проверяет каждую цитату по исходному тексту. Кандидаты не обновляют сведения автоматически: выбор фактов → проверка отрицаний / замены → проект существующего редактора → отдельное сохранение врача. Неуверенные факты и отрицание отдельного пункта нельзя переносить как отсутствие всего раздела. Сохранение повторно проверяет источник, цитату и версию сведений. Проверки выполняются на синтетических ответах адаптера; реальный API ещё не испытывался.

## Email и фоновые задачи

Для подключения нужны `ALERT_EMAIL_ENABLED=true`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, доступный корневой HTTPS `APP_ORIGIN` и соответствующий `BETTER_AUTH_URL`. Для синтетических событий дополнительно `DEMO_MODE=true` и `ALLOW_DEMO_ALERT_EMAIL=true`. Секреты храните в окружении; шаблон полей — `.env.example`. Настройки локального HTTP не подходят для включения email. Реальных писем при разработке не отправляли.

Письмо содержит нейтральное уведомление и ссылку на конкретное событие после входа. Медицинский текст и имя пациента в письмо не копируются. Задание создаётся в одной транзакции с событием. Отдельный пул уведомлений не ждёт долгого импорта. Доступны статусы отключённого канала, очереди, отправки, принятия SMTP, ошибки и неизвестного результата. Неизвестный исход не повторяется автоматически; ручной повтор требует признать риск дубликата. SMTP не доказывает доставку в ящик, прочтение или наличие экстренного дежурства.

## Эксплуатационные команды

`npm run db:backup` создаёт локальную копию с SHA-256 и манифестом; `npm run db:restore-check` восстанавливает её в отдельную временную БД, сравнивает счётчики и удаляет только эту временную БД. Основная база не пересоздаётся. Копии в `.local/backups` содержат приватные данные и остаются локальными; независимое хранение / RPO / аварийный регламент ещё не настроены.

`npm run measure:read` создаёт очищаемую синтетическую фикстуру (120 пациентов, 4200 отметок) и сохраняет локальные p50 / p95 / размеры ответов в `.impeccable/review/read-measurement.json`. Это измерение ограниченной нагрузки чтения, не гарантия производительности продакшена.

`.github/workflows/verify.yml` готовит PostgreSQL с ICU, сборку и проверки. Удалённый CI ещё не запускался. Применены 11 добавочных миграций. Публичное развёртывание на фактическом домене и клинические материалы остаются отдельными незавершёнными условиями; редактор контента не добавляется.


## Когда появятся анкеты и клинические материалы

Добавляем их в код, без отдельной админки. Контракт и чистый расчёт находятся в `src/modules/clinical`, образец — `demo-definition.ts`. Опубликованная пара code/version неизменяема: исправление создаёт новую версию через `publishDefinition`, старые ответы сохраняют своё определение и checksum. Существующий seed специально ограничен DEMO и не превращается в клинический простым снятием маркировки.

Для каждого реального инструмента нужны точный текст / варианты / период, формула, интерпретация, источник и проверенные примеры. Если формула не поддерживается текущим движком, добавляется отдельный проверяемый расчёт с версией; баллы не вычисляются моделью. Клинические действия расширяют `modules/monitoring/action-catalogue.ts` только вместе с условиями, ограничениями и источниками. Фактические вопросы / пороги / лекарственные рекомендации сейчас не подставлены.


## Контейнерный контур демонстрации

Добавлен отдельный Compose для web / worker / PostgreSQL и необязательного HTTPS-прокси, с отдельными секретами, базой и портом 3080. Подробные команды, обновление, остановка и ограничения: [infra/deploy/README.md](infra/deploy/README.md). `npm run deploy:prepare` создаёт конфигурацию один раз; `npm run deploy:check` проверяет настроенный синтетический контур после явного seed. Локальная разработка на 3000 продолжает использовать свою базу.

`/api/health` проверяет соединение с БД; `/api/ready` требует ещё и свежую отметку готовности worker. При недоступном worker статус готовности 503 не означает потерю уже сохранённых данных. Для подготовки очереди / heartbeat требуется одиннадцатая добавочная миграция и обновлённый worker. Проверки используют только технические статусы и `Cache-Control: no-store`.

Полный E2E-прогон выполняется с остановленным локальным worker: тесты доставки сами вызывают подставной обработчик и проверяют задания очереди, поэтому фоновый потребитель не должен конкурировать с фикстурой. CI сначала проверяет запуск worker / readiness, завершает worker и затем запускает регрессию; по окончании ручного прогона worker снова запускается. Docker-контур имеет независимую БД и не влияет на эти фикстуры.

## Уведомления сайта (Web Push)

В кабинете врача значок телефона в верхней панели открывает подключение устройства, тестовую отправку и отключение устройств. Разрешение браузера запрашивается только по нажатию. При появлении нового события по анкете отправка ставится в очередь в той же транзакции; push открывает точное событие, в том числе после повторного входа. На экране блокировки нет имени пациента, ответов и диагноза. Рекомендации остаются в защищённой панели события.

Для локальной учебной версии выполнен `npm run push:configure-local`: постоянные VAPID-ключи хранятся только в игнорируемом `.env`, web и worker используют одну пару. Повтор команды сохраняет ключи. Это включает серверный канал, но не подписывает устройства автоматически. Удалённый контур по умолчанию выключен: нужны HTTPS-адрес, `WEB_PUSH_ENABLED=true`, постоянные `WEB_PUSH_PUBLIC_KEY` / `WEB_PUSH_PRIVATE_KEY` и `WEB_PUSH_SUBJECT` с действительным контактом оператора. Для учебных событий отдельно `ALLOW_DEMO_WEB_PUSH=true`. Не используйте демонстрационный контакт `push@kontur.demo` как контакт реальной клиники.

На компьютере работает localhost; телефон должен открывать доступный ему HTTPS-сайт. На iPhone/iPad нужны iOS/iPadOS 16.4+, добавление на экран «Домой» и запуск с иконки. Подключение привязано к действующей серверной сессии: после выхода/истечения входа требуется явное переподключение. Иные устройства отключаются отдельно, максимум пять действующих устройств на врача.

Статусы различают очередь, принятие push-сервисом и сообщение браузера о показе. Они не подтверждают прочтение или реакцию врача. После явного технического отказа допускается максимум три попытки; неизвестный исход не повторяется автоматически. Событие остаётся в кабинете при любом результате доставки. Почта сохранена отдельным необязательным каналом, автоматически при отказе push она не включается. Порядок реакции клиники на критические события требует отдельного согласования.

Проверки транспорта используют подставной отправитель и синтетические подписки, не обращаясь к реальным push-сервисам. Подключение настоящего телефона и фактическая доставка через его провайдера пока не проверены. Service worker не кэширует страницы и медицинские данные. Docker для этого пакета не запускался.

## Рекомендации F40 и проверочный перенос BAI

В выборе анкеты врача появилась «Шкала тревоги Бека (BAI)»: 21 пункт из предоставленного PDF, последняя неделя, ответы 0–3, сумма 0–63. Пациент отвечает небольшими блоками в одной панели, сохраняет черновик и продолжает с первого незаполненного блока после перезагрузки. Высокий диапазон 36–63 по ключу этого PDF создаёт одно проверочное событие с числом, причиной, исходными ответами, действиями и ссылками на нужные страницы. Срабатывание не является диагнозом, суицидальным риском или автоматической экстренной категорией.

Исходный PDF хранится вне public, выдаётся вошедшему пользователю через /api/clinical-source и проверяется по SHA-256. Он включён в standalone-сборку. Подробности источника, страницы, расхождения и границы — CLINICAL_SOURCE_REVIEW.md. Это подключение одного документа, не универсальный импорт PDF/DOCX историй болезни.

Перенос опубликован только в DEMO. Для него действует серверная граница 18+, а клиническое одобрение не присваивалось: в приложении Г5 есть неточная библиографическая ссылка, актуальность редакции/русскую версию/условия цифрового использования нужно отдельно проверить. Сохраняются условия проверенного клинического выпуска. Полный seed пациентов не нужен: только `npm run db:seed-assessments` для идемпотентной публикации определений. Новых миграций нет. Для депрессии, ГТР и панического расстройства потребуются соответствующие источники.


## Импорт файлов и бесплатное облачное извлечение — 21 октября

В панели «Из истории болезни» → «Добавить документ» можно вставить текст либо выбрать PDF / DOCX. Файл до 5 МБ; PDF до 50 страниц; извлечённый текст до 60 000 символов. Сначала показывается текст, затем врач явно сохраняет документ. AI при загрузке не вызывается. Сканы и рукопись требуют отдельного OCR. Для смешанного PDF показывается количество страниц без достаточного текстового слоя; порядок таблиц нужно сверять с оригиналом.

Оригинальные байты, SHA-256, имя, тип и версия парсера сохраняются в закрытой БД. Скачать исходный файл может только ведущий врач. JSON/списки не содержат бинарный файл; старые вставленные тексты доступны как прежде. Миграция `20261021000000_document_files` добавочная, полный seed не нужен.

Актуальное локальное подключение — **Mistral / ministral-14b-latest**. Одна дата следующего приёма, уведомления о назначении и завершении анкет и проверка LLM описаны в [обновлении от 24 октября](docs/updates-2026-10-24.md). Ниже сохранена инструкция для альтернативного Groq-подключения. Локальные модели не устанавливаются и не запускаются. Для подключения создайте ключ в https://console.groq.com/keys и добавьте его только в локальный `.env`: `GROQ_API_KEY=...`. Затем:

```powershell
npm run llm:configure
npm run llm:check
# После успешной проверки перезапустите web и worker.
```

`llm:configure` выбирает Groq и включает извлечение только при наличии ключа; остальные секреты сохраняет. Требуется `DEMO_MODE=true`. `llm:check` отправляет только встроенный вымышленный пример, не выводит ключ или ответ провайдера. `npm run llm:evaluate` запускает шесть синтетических контрольных случаев с паузами по квотам и сохраняет отчёт `.local/llm-evaluation.json`. Это небольшой технический набор, не клиническая валидация.

Бесплатный тариф имеет квоты, указанные в FREE_LLM_RESEARCH.md. В текущем приложении для Groq действует предел **8 000 символов** на извлечение и 2048 токенов ответа. Длинный документ можно сохранить полностью; модель его молча не обрезает. Ошибки квоты и незавершённый JSON не становятся кандидатами. Платного автоматического fallback нет. Для альтернативного явно настроенного OpenAI остаётся прежний адаптер; он не выбирается после ошибки Groq.

Текст передаётся облачному провайдеру только после отдельного подтверждения. Groq-подключение здесь рассчитано на вымышленные демонстрационные данные; реальные медицинские данные и пригодность облака для них не допущены. Ключ не отдаётся браузеру. Цитаты проверяются локально, выбор фактов только готовит черновик, публикация сведений остаётся отдельным действием врача. Баллы анкет, диагнозы, срочность и назначения LLM не вычисляет.

`npm run build` сам собирает изолированный Node-парсер; системные PDF/Word-утилиты не требуются. Нативный web/worker/PostgreSQL работают без Docker.
